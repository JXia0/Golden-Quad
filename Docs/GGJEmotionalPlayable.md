# 《放开我的手》：明天下午 16:00 前的可玩情绪版本

本次方向由作者确认：**成长必须告别——失落、不舍，最后接受离开。**

分工更新：本任务负责产品把控、程序和核心玩法，负责确定取舍与整体验收；正式美术与效果由美术和 5.6 sol 执行。接口见 [程序与呈现交接](GameplayPresentationHandoff.md)。下文的美术、音效条目是交接参考，不由本任务制作或调整。
目标是 6–8 分钟的首次体验，以盲测计时为准，不用长路、长读条或强制等待凑时长。能否入围需要实际试玩与活动评审，不能由这份方案保证。

## 现有版本为什么像流程而不像完整游戏

原文档已经有很好的主题，但实际规则没有兑现它：

- 幼儿园的座位是按一下完成任务；玩具使用另一套单击背包；孩子是匀速跟随物体。玩家不需要读懂另一个人的状态。
- 舞台只要走进路线触发器就记录选择，高处站位没有承托呼吸的实体平台。站位尚未成为真正的表演决定。
- 研究关第一次投递就锁掉另一份材料，材料之间主要是名称和颜色不同；玩家尚未观察，就被要求“负责”。
- 勇气耗尽会自动重生。它实际惩罚停留，与允许犹豫和回头冲突。
- 结尾年轻人没有进门动作，松手后直接切黑，缺少“手空了以后”的时间。

改动的标准：**一个物件至少改变一次玩家的行动，或留下玩家能看到的结果。** 不以任务数、设定字数或系统数量衡量丰富度。

## 当前已接入的玩法

### 幼儿园：先把自己的东西放下，再接住别人的手

1. 牵父母到门前，光线拉紧；松开后自己跨过门槛。父母仍在原处，可以返回。
2. 门内有一只书包。按住抱起，松开放在自己的椅子上，书包留在椅子上。座位不再通过单击确认名字。
3. 地上的玩具使用同一套按住携带、松开放置的操作。在哭泣孩子身边放开，他把玩具抱在身侧。
4. 牵孩子去老师那里。距离拉得过长时，他停住；靠回来等约 0.8 秒，胸口的圈舒展开，他再迈步。正常慢走不需要反复触发停步。
5. 到老师身边放手，孩子自己走出去。玩家留下空着的手，环境平静下来。

实际任务链是：过门 → 留下书包 → 递出玩具 → 陪伴并放手。没有额外的对话交付按键。

希望玩家产生的是“原来我也会拉得太急”，不是“这只 NPC 走得真慢”。如果盲测出现后者，先提高跟随速度或放宽张力阈值，不能用解释字幕补救。

### 舞台：让呼吸变成真实的三句表演

1. 第一个站位吸气、完整蓄气后松开，声音以一道扩散的光传播，地面留下第一句的波形。
2. 第二句有低处和高处两个站位。走过不算选择；在哪里停稳、呼吸并松开，才在哪里留下表演。高处添加单向平台，能跳上去站住。
3. 最后一个站位完成第三句。三道灰盒波形保留，任务完成并调用已有掌声音效。聚光灯与幕布效果由呈现任务订阅发声事件处理。
4. 空椅子与暖色围巾是交给美术的环境叙事建议，不由程序自动放置，也不把“父母去世”等背景强加给玩家。

没有精确节拍评分，没有因为声音发抖重新开始。按住是聚拢自己，松开才让声音到达外面。正式音频应让三次发声有区别，当前复用已有呼吸音效。

### 研究：允许改主意，最后一次放手才定稿

1. 把问题卡放到问题板，两种方案的微型路径显现。
2. 携带照片或数据到工作灯下，停约 1.1 秒观察，路径由暗变亮。照片路径有起伏和停靠，但没有延伸到门；数据路径更直接，人物在临门处仍有迟疑。
3. 松开放到证据板，选择成为草稿。可以返回取另一份替换；旧材料回到原处，进度不会重复增加。
4. 抓住结论卡，送到结论板，松手定稿。这时才锁住草稿；未采用的方案仍能看到，怀疑没有完全消失。

当前路径、人形和门是程序生成的灰盒示意。它们是“尚未覆盖的情况”的视觉比喻，不是严谨的科学实验或互相排斥的科学证据。交稿前优先把两份卡的画面做成同一个问题的两个具体观察，而不是只写“照片”和“数据”。

建议统一物件问题：**一个第一次来到陌生地方的人，要怎样走到门里？** 照片显示熟悉座位带来的停靠，数据显示距离缩短但无法解释的门前停顿。保留“研究与汇报”场景，但让它回望玩家刚经历过的幼儿园和舞台。

### 结尾：对方离开之后，玩家仍然需要走

过去的空间选择继续通过原有记忆物件回放。

年轻人握住玩家的手时，呼吸光圈慢慢舒展。玩家不松手，他就不走；提前松手不会直接结束，需要重新稳定他。

完整牵手后松开，年轻人实际走进门，玩家在原地短暂停下。人消失后恢复操作。**系统不替玩家切黑；玩家必须自己向右走过门边，才触发结尾。** 允许多站一会儿；约 4 秒后才给一个方向键提示。

结束保留标题和“谢谢你，陪我走到这里。”，移除解释成长道理的总结。Enter 可以重玩。

## 工程接入和美术协作

- 正式五个场景和 Build 顺序不变，不执行全场景重建。
- `StorySceneDirector.Start` 调用 `EmotionalJourney.Install`；它只在 Play/Build 中补齐三个章节的组件和新增物件，隐藏旧说明标签、旧任务计数及勇气条。退出 Play 后恢复原始场景排版。
- 所以编辑态仍会看见旧任务标签，运行时才是新版流程。不要在 Play 中调整后误以为布局已保存。
- 新增物件统一挂在场景的 `Story Scene Director` 下；现有交互锚点用保存的物体位置。已有美术可继续替换。
- `JourneyArtImporter` 自动生成 `Assets/Resources/JourneyArtPalette.asset`，让新增物件在正式 Build 中也拥有贴图引用。可通过 `Tools > Let Go > Refresh Emotional Journey Art` 手动刷新。
- 保持锚点名称不变：`Oversized Chair`、`Teacher Safe Area`、三个 Breath/Release Cue、两条 Route、`Forward Platform`、三个研究 Board、`Unknown Door`。运行时安装与检查使用这些锚点。

## 到提交前的安排

1. 先通完整流程：检查出生点、交互范围、椅子与积木、高台、三块板、最后一步，无卡死。
2. 找 2–3 个没读设定的人，单人试玩，作者不要讲解。记录首次卡住超过 20 秒的位置、是否主动回头、是否发现孩子在等、是否知道草稿能换、结尾是否自行继续走。
3. 只修最影响理解的两处。优先物件轮廓、空间距离和声音反馈，最后才增加一句简短操作提示。
4. 明天下午预留至少 2 小时打包、在另一台电脑从头跑到尾、检查音量/分辨率/重玩及提交文件。停止扩展系统和章节。

通过标准：不看设定，玩家也能说出“我把自己的东西留下了”“他在等我”“我还可以改主意”“这次得让我自己走”。如果只能复述开场旁白，就继续修行为和反馈。

## 验证入口

- `Tools > Let Go > Validate Emotional Journey`：在临时场景里检查替换、定稿、取消连接、物品落地、孩子停步和保存场景锚点，不保存游戏场景。
- `Tools > Let Go > Run Emotional Journey Playthrough Checks`：要求当前场景已保存，用真实键盘输入事件和 Unity 物理自动跑三幕与结尾，结束后恢复原先打开的场景。结果在 `Logs/JourneyPlaythroughChecks.txt`。
- 逻辑检查和自动通关不能证明情绪成立。最终以第一次接触游戏的真人试玩为准。
